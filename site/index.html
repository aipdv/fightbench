Method

  • Same save states, same 17 moves, same prompt, same seeds for every row.
  • Rank is mean damage dealt, high to low. Wins are reported, not ranked.
  • script is the rules-bot floor. random picks uniformly from the 17 moves. Both call no model, so they cost $0.
  • A new model version or track is a new row. A new prompt or temperature is a new edition.
  • Replay re-runs the game from the submitted answers and checks the outcome. It does not re-call the model, so the model name, cost, and latency are attested by the submitter.
  • Survival is the mean round length in seconds. Top moves is the share of decisions per move.
  • Smoke rows (one fight, one round) are grey and sit below official rows.
  • This page renders board.json. A GitHub Action rebuilds it from results/verified/ on every merge to main.

Submit

Bring your own ROM. Nobody ships a ROM.

uv run mk2_clef.py --rom <your file>                     # install your ROM
uv run fightbench.py table --policy my.py:MyPolicy        # or: live --policy my.py:MyPolicy
git add submissions/ && git commit && gh pr create        # commit only your submissions/ file

Write a Policy class (see fightbench.py). Set usage to report tokens and $; the harness times each call. The maintainer runs uv run fightbench.py replay pending on the PR and merges. The board updates itself.
